# OV-20261029-print-output: the file name and byte layout of PRINTFILE / PRINT_VALUE / PRINT_STRING
Date: 2026-10-29
Status: confirmed (re-read of existing runs, no new launch)
Observer: OpenVirtue maintainers (black-box probe outputs)
Implementer: OpenVirtue maintainers

## Question
Every trace probe since OV-20261009-shoot-mapping writes its results with `PRINTFILE`,
`PRINT_VALUE` and `PRINT_STRING`. The oracle-diff harness (`ovtool oracle diff`) compares those files
with the ones OpenVirtue writes for the same carrier, so the two must agree byte for byte where the
script is the same. What file name does `PRINTFILE "name", 0` produce, does `PRINT_VALUE` add
anything after the number, and what does `\n` inside a `PRINT_STRING` write?

## Why It Matters
OpenVirtue wrote `<name>000.TXT` (three-digit number, the manual's wording), appended a host line
break after every `PRINT_VALUE`, and turned `\n` into the host line break (CR LF on Windows). Any
retail script that prints, and every harness comparison, depended on the difference.

## Clean-Room Boundary
- Oracle used: the trace files already written by the patched DOS runtime (V3.963) in the
  OV-20261009 to OV-20261021 runs; nothing new was launched.
- Reference material consulted: the 1998 A3 manual p.88 (`PRINTFILE`: "string (max. 5 characters)
  plus a 3-digits number plus extension .TXT", default name `PRINT0.TXT`; `PRINT_VALUE`: the skill
  "as number with 3 decimals"; `PRINT_STRING`: `\n` creates a line feed).
- Split-role mode used: not needed (black-box).
- Local-only artifacts: `_research/oracle-runs/OV-2026*/**/work/OV*.TXT`. Example hashes (sha256,
  first 8): distance-refresh near-hook `OVDRX0.TXT` `aaca2380`, each-sec-cadence cadence
  `OVSEC0.TXT` `8b674d8a`.
- Confirmation that no proprietary code/assets are committed: synthetic carriers only.

## Setup
The carriers (generated by `ovtool oracle prepare`) select files with `PRINTFILE "ovxxx", 0` (the
base name in lower case) and write lines such as `PRINT_STRING "C"; PRINT_STRING " ";
PRINT_VALUE TICKS; PRINT_STRING "\n";`. Native Linux DOSBox-X mounts `work/` as C:, so the files
appear there with the names DOS gave them.

## Observations
| Item | Evidence | Reading |
|---|---|---|
| File name | 125 carriers with `PRINTFILE "ovend", 0` wrote `OVEND0.TXT`, likewise `OVSTA0.TXT`, `OVPRB0.TXT` and every trace file (`OVDRX0.TXT`, `OVSEC0.TXT`, …); none wrote `OVEND000.TXT` | the number is written without padding and the name is upper case (a DOS 8.3 name) |
| `PRINT_VALUE` | a byte dump of `OVDRX0.TXT` reads `G O ␠ 1 6 . 2 5 0 ␠ 0 . 0 0 0 …` with no break between a value and the next `PRINT_STRING " "` | the value is written with three decimals and nothing after it |
| `\n` | the same dump has `0x0A` alone at every line end, no `0x0D` | `\n` writes a bare line feed, also on DOS |

Not measured: numbers above 9 (whether `PRINTFILE "x", 12` gives `X12.TXT`), negative values, and
what happens past the five-character base.

## Invariant
`PRINTFILE "name", n` selects `NAME<n>.TXT` (upper case, the number in plain decimal). `PRINT_VALUE`
appends the value with three decimals and no separator. `\n` in a `PRINT_STRING` appends one line
feed byte (0x0A) on every host.

## Addendum: exact halves (2026-11-03, analysis only)
A value on the 1/1024 grid that is an odd multiple of 1/16 (13.5625, 0.0625) lies exactly between
two three-decimal prints. Over every trace the original wrote under `oracle-runs/`, the printed
endings that such halves would give rounded up (`…063`, `…188`, `…313`, …) appear 8323 times, the
endings rounding to even would give 137 times (and those can come from values that are not halves);
for negative values, away from zero 446 times against 49. eye-clamp's stop-border prints −7.813 for
−7.8125 (`OVECX0.TXT` `afdac5e6`), and the shoot-mapping depth sweep 34.063 for 34.0625. So
`PRINT_VALUE` rounds an exact half away from zero. OpenVirtue printed with .NET's `F3`, which rounds
it to even (13.562); the harness's 0.002 tolerance had hidden the difference.

## Implementation
`WdlRuntime.PrintValue` (`FormatPrintValue`)/`PrintFilePath`/`NormalizePrintBaseName` and the `PRINT_STRING` escape in
`WdlInterpreter`; `WdlRuntimeTests.Runtime_PrintInstructions_AppendToSelectedTextFile`,
`FormatPrintValue_ExactHalves_RoundAwayFromZero` and
`RuntimeHostFrameClockTests.Frame_PrintInstructions_WriteTheDosFileNameAndLayout` pin it.
