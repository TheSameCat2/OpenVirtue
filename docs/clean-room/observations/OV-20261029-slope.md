# OV-20261029-slope: which flags tilt a region by its vertex heights
Date: 2026-10-29
Status: confirmed (two rounds; round 1 failed to compile) and implemented
Observer: OpenVirtue maintainers (black-box probe, trace values)
Implementer: OpenVirtue maintainers

## Question
A WMP vertex carries a height (its Z). When does that height tilt a region's floor or ceiling, and
in which direction? The manual names `FLOOR_ASCEND`/`FLOOR_DESCEND` and `CEIL_ASCEND`/`CEIL_DESCEND`;
the retail levels also use `FLOOR_LIFTED` and `CEIL_LIFTED`, which it does not describe, and many of
their regions share sloped vertices without carrying any flag.

## Why It Matters
OpenVirtue tilted every region whose vertices had a height, raising both surfaces. In the retail
levels this tilted flat rooms that border a ramp.

## Setup
Native Linux DOSBox-X 2026.10.01, `forcerate=60`; carriers from `ovtool oracle prepare slope`
(`tools/OpenVirtue.Tools/SlopeProbeCases.cs`). A square pad region (floor 0, ceiling 16) with the
corners (−12,12), (−4,12), (−4,20), (−12,20) at the heights 0, 2, 4, 2; each case sets one flag set
on the pad. The player is beamed to the points P0 (−11,13), P1 (−5,13), P2 (−5,19), P3 (−11,19) and
the centre, and each point prints `FLOOR_HGT` and `CEIL_HGT`. Round 1 also printed `PLAYER_REGION`,
which `PRINT_VALUE` rejects ("Error(66)"), so nothing ran.

## Observations
| Case | `FLOOR_HGT` at P0, P1, P2, P3, centre | `CEIL_HGT` at the same points |
|---|---|---|
| no flag | 0, 0, 0, 0, 0 | 16 everywhere |
| `FLOOR_ASCEND` | 0.5, 2, 3.5, 2, 2 | 16 everywhere |
| `FLOOR_DESCEND` | −0.5, −2, −3.5, −2, −2 | 16 everywhere |
| `FLOOR_LIFTED` | as `FLOOR_ASCEND` | 16 everywhere |
| `CEIL_ASCEND` | 0 everywhere | 16.5, 18, 19.5, 18, 18 |
| `CEIL_DESCEND` | 0 everywhere | 15.5, 14, 12.5, 14, 14 |
| `CEIL_LIFTED` | 0 everywhere | as `CEIL_DESCEND` |
| `FLOOR_ASCEND, CEIL_ASCEND` | as `FLOOR_ASCEND` | as `CEIL_ASCEND` |

The readings lie on the plane through the four corners (the corners are coplanar: 0 + 4 = 2 + 2).

## Invariant
Without a slope flag a region's floor and ceiling are flat at their declared heights, whatever
the vertex heights are. `FLOOR_ASCEND` and `FLOOR_LIFTED` add the vertex heights to the floor;
`FLOOR_DESCEND` subtracts them. `CEIL_ASCEND` adds them to the ceiling; `CEIL_DESCEND` and
`CEIL_LIFTED` subtract them. Between the corners the height follows the plane they span. The floor
flags and the ceiling flags act independently.

## Open Questions
- Which flag wins when a region sets both `ASCEND` and `DESCEND` (OpenVirtue takes `ASCEND`).
- Non-planar regions: whether the original interpolates per triangle or fits one plane.

## Implementation
`LevelTopology.SlopeSign`, `FloorHeightAt` and `CeilingHeightAt` feed `MeshBuilder` (floors, ceilings
and the wall ends), `Player`, `SpriteBuilder` and the actor height skills in `WdlRuntime`; tests in
`SlopeTests` reproduce the table.
