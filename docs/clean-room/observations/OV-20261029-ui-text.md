## Question
How does a `TEXT` of several lines appear: `STRINGS` with several strings, "\n" inside a string,
`OFFSET_Y`, `SIZE_Y`, and `CENTER_X`/`CENTER_Y` (manual p.129–131)? The manual says `SIZE_Y`
suppresses characters outside the range and `OFFSET_Y` scrolls "pixel by pixel". It does not say
whether a line can be partly shown, or what `CENTER_Y` centres for several lines.

## Why It Matters
The retail menus, credits and message lines are multi-line texts.

## Setup
- Carriers: `ovtool oracle check ui-text` (`tools/OpenVirtue.Tools/UiTextProbeCases.cs`).
- Font: the ui-layout font (8 × 8, character c in palette index 64 + c).
- Text: at (300, 200), with `STRINGS 3` showing "AB", "CDE" and "F", or one string "AB\nCD".

## Observations
| Case | Lines drawn (top y) |
|---|---|
| three strings | AB 200, CDE 208, F 216 |
| "AB\nCD" | AB 200, CD 208 |
| `OFFSET_Y 3` | CDE 205, F 213 (AB, at 197, not drawn at all) |
| `SIZE_Y 12` | AB 200 only (CDE, ending at 216, not drawn) |
| `OFFSET_Y 3`, `SIZE_Y 12` | nothing (CDE at 205 would end at 213) |
| `CENTER_X`, `CENTER_Y` | AB at x 292, y 196; CDE at x 288, y 204; F at x 296, y 212 |

## Invariant
- **Lines.** A `TEXT` draws its strings one line each, a font height apart, and "\n" starts a new
  line.
- **Clipping.** A line is drawn only when it lies wholly between `POS_Y` and `POS_Y + SIZE_Y`
  after `OFFSET_Y` moves it up. A line partly outside is left out, not cut.
- **Centring.** `CENTER_X` centres each line on `POS_X`. `CENTER_Y` centres the first line on
  `POS_Y`, and the others follow below it.

## Open Questions
- Where the clip range starts for a `CENTER_Y` text (OpenVirtue uses the centred first line's top).
- 256-character fonts and characters outside the font.

## Implementation
`UiTextBuilder.AddTextGlyphs`; tests `UiTextBuilderTests.Build_SizeYAndOffsetY_ShowOnlyWholeLines`
and `Build_CenteredText_UsesPosAsCenter`.
